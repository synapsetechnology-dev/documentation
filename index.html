How it Works

Updated: Sep 2026 4 min read Architecture

Understanding the data lifecycle, execution engine, and modular event flow of Synapse Technology.

Core Architectural Flow

Synapse follows an event-driven decoupled architecture. When an action occurs (e.g. a customer makes a purchase, a webhook is fired, or a scheduled cron job executes), the core kernel dispatches an event through prioritized message queues.

1
Trigger Event Ingestion
Events arrive via HTTP Webhooks, Scheduled Cron jobs, or Admin UI interactions. Incoming payloads are validated against strict schema rules.
2
Conditional Logic Evaluation
The Synapse Workflow Engine processes the configured filter nodes (e.g., "if total > $50" or "if user status is active").
3
Action Execution & Dispatch
External API calls (OpenAI, Stripe, SMTP, Webhooks) are processed asynchronously in worker queues to guarantee sub-millisecond page response times.
Queue Worker Tip
For high-volume production setups, running Supervisor to monitor php artisan queue:work --tries=3 delivers optimal performance and fault tolerance.

Quick Start Guide

Setup: 5 mins Difficulty: Easy Installation

Follow this 3-step rapid setup guide to deploy Synapse to your production server or local testing environment.

Step 1: Upload Files & Set Permissions

Extract the zip file downloaded from CodeCanyon and upload the files inside the /script/ folder to your web server root (typically public_html or your Nginx/Apache virtual host directory).

bash

  • Database Name: synapse_db

Step 3: Run the Web Installer

Open your browser and visit your site domain:

browser

Server Prerequisites

Nginx Configuration Example

/etc/nginx/sites-available/synapse.conf 
server {
    listen 80;

    add_header X-Frame-Options "SAMEORIGIN";
    add_header X-Content-Type-Options "nosniff";

    index index.php;
    charset utf-8;

    location / {
        try_files $uri $uri/ /index.php?$query_string;

    location ~ \.php$ {
        fastcgi_pass unix:/var/run/php/php8.2-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include fastcgi_params;
    }
}

Always verify that APP_ENV=production and APP_DEBUG=false in your .env file. Setting debug to true on a public live domain exposes internal database credentials and API keys in exception traces.

4. Nginx Server VirtualHost (Ubuntu 22.04 / 24.04 VPS)

Create a new server block at /etc/nginx/sites-available/synapse.conf pointing to the /public directory with gzip, security headers, and PHP 8.2-FPM:

/etc/nginx/sites-available/synapse.conf 
server {
    listen 80;
    listen [::]:80;
    server_name yourdomain.com www.yourdomain.com;
    root /var/www/synapse/public;

    index index.php index.html;
    charset utf-8;

    # Security Headers
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Referrer-Policy "no-referrer-when-downgrade" always;

    # Gzip Compression
    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location = /favicon.ico { access_log off; log_not_found off; }
    location = /robots.txt  { access_log off; log_not_found off; }

    # PHP-FPM Processing
    location ~ \.php$ {
        fastcgi_pass unix:/var/run/php/php8.2-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include fastcgi_params;
        fastcgi_hide_header X-Powered-By;
        fastcgi_read_timeout 300;
    }

    # Deny access to hidden files (.env, .git)
    location ~ /\.(?!well-known).* {
        deny all;
    }
}

Enable the site and obtain a free Let's Encrypt SSL certificate:

bash 
# Enable virtualhost and test configuration
sudo ln -s /etc/nginx/sites-available/synapse.conf /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx

# Install SSL Certificate via Certbot
sudo certbot --nginx -d yourdomain.com -d www.yourdomain.com

5. cPanel & Shared Hosting Deployment

When deploying on standard cPanel hosting:

  1. Domain DocumentRoot: Set your domain's DocumentRoot in cPanel to public_html/public instead of public_html.
  2. MultiPHP Manager: Open MultiPHP Manager in cPanel and set your domain's PHP version to PHP 8.2.
  3. MySQL Database: In cPanel, click MySQL Database Wizard, create database cpaneluser_synapse, create user, and check ALL PRIVILEGES.
  4. Run Web Installer: Open https://yourdomain.com/install in your browser and complete the 4 steps.

6. Supervisor Queue Workers & Cron Scheduler

On high-volume production setups, background workers handle WhatsApp notification queues, PDF invoice generation, and database syncs without slowing down customer checkout.

/etc/supervisor/conf.d/synapse-worker.conf 
[program:synapse-worker]
process_name=%(program_name)s_%(process_num)02d
command=php /var/www/synapse/artisan queue:work database --sleep=3 --tries=3 --max-time=3600
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
user=www-data
numprocs=2
redirect_stderr=true
stdout_logfile=/var/www/synapse/storage/logs/worker.log
stopwaitsecs=3600

Activate Supervisor and configure the system crontab:

bash 
# Reload and start Supervisor
sudo supervisorctl reread
sudo supervisorctl update
sudo supervisorctl start synapse-worker:*

# Add Laravel schedule worker to system crontab (crontab -e)
* * * * * cd /var/www/synapse && php artisan schedule:run >> /dev/null 2>&1
